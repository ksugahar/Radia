## Phased Execution Order

Each phase is its own session-bounded batch. Within every promote-then-prune
batch the rule is: (1) author the tracked `docs/<topic>/*.ipynb`, (2) migrate
every test / MCP-knowledge / panel / docs reference to point at the new
notebook, (3) ONLY THEN delete the source `.py`, (4) distill any lasting
lesson to `memory/` before deleting prune-class scratch.

safest topics. Zero-reference topics need no migration; single-reference
topics need exactly one knowledge line re-homed.

lesson to memory/: `ngsolve_user_meeting`, `jou_translation_bench`,
`effective_surface_impedance` (also removes a Binary-Policy-violating .pkl).
