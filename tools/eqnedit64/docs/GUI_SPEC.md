# Eqnedit64 GUI仕様

- 仕様版: 1.0
- 対象: Eqnedit64 3.0.5
- 基準日: 2026-08-25
- 適用範囲: `dist\Eqnedit64.exe`

この文書は、Eqnedit64の画面、操作、状態遷移、ファイル、クリップボード、
受入試験の基準仕様である。キー割当の完全な一覧は
[`SHORTCUTS.md`](SHORTCUTS.md)、手動確認手順は
[`OPERATION_DEBUG_GUIDE.md`](OPERATION_DEBUG_GUIDE.md) を正とする。Web/JS版との
共通中核と固有機能の境界は [`PRODUCT_PARITY.md`](PRODUCT_PARITY.md) を正とする。

## 1. 製品目的

Eqnedit64は、Eqnedit32の軽快な数式入力を、標準のUTF-8 TeXへ直結する
64-bit Windows数式エディタである。主眼は、文章編集やDTPではなく、
手を止めない数式入力、構造編集、複数行数式、他アプリへの再利用である。

### 1.1 必須の製品契約

- 保存形式はUTF-8 `.tex` だけとする。
- 新規数式は `equation` 環境として保存する。既存の `equation*` 文書を開いた場合は、
  保存時にもその外枠を維持する。
- 複数行は内側の `aligned` 環境で表現する。
- 構造編集キャンバスとTeXソース欄を同時に表示し、どちらからも同じ数式を
  リアルタイムに編集できること。
- キャンバスからの1回のコピーで、TeX、EMF、PowerPointのMicrosoft数式を
  利用できること。
- Google スライド用コピーは300 dpi画像を24 pt基準の物理寸法で貼れること。
- 配布物は `Eqnedit64.exe` 1ファイルだけとする。
- 配布exeは署名者 `ksugahar` の有効な
  Authenticode開発者署名を持つこと。

### 1.2 非目標

- `.eqn` / MTEFの入出力
- OLEオブジェクトとしての埋め込み
- インストーラー、レジストリ登録、スタートメニュー登録
- 汎用TeX文書エディタ、プリアンブル編集器、TeX組版エンジン

## 2. 起動と配布

- `Eqnedit64.exe` を直接実行する。Python、`.pyd`、VC++再頒布ランタイム、
  外付けDLLを必要としない。
- ファイルパスを第1引数に渡した場合は、その `.tex` を開く。
- 通常起動時の新規数式は空、保存外枠は `equation`、未保存である。見本を入れておくと、
  利用者が最初にする操作がその削除になるため入れない。
- 開発者署名は研究室内の自己署名証明書である。公開CAの信頼やSmartScreen評価とは
  区別し、ビルド機では公開証明書をCurrentUserの信頼されたルート／発行元へ登録する。
- 初期ウィンドウサイズは1060×680 logical pixelsとし、Per-Monitor DPI Aware V2で
  スケーリングする。
- アプリケーションアイコン、バージョン情報、第三者ライセンスはexe内に収録する。

### 2.1 保存したTeXが要求するパッケージ

保存されるのは `equation` 環境の断片なので、前文は取り込み先の文書が持つ。
`amsmath` に加えて、次のコマンドを使った式は追加パッケージを要求する。

| コマンド | 必要なパッケージ | 出所 |
|---|---|---|
| `\therefore` `\because` `\nexists` `\varkappa` | `amssymb` | 記号パレット |
| `\cancel` | `cancel` | 装飾パレットの打ち消し線 |

`\oiint`（閉曲面積分）と `\oiiint`（閉体積分）は**テンプレートとして提供しない**。
前者は `esint`、後者は数式フォントごと差し替えるパッケージにしか無く、
論文側にその依存を強いることになるため。貼り付けられたものは表示できる。

`tests/test_tex_compiles.py` が、記号表とテンプレートのすべてを実際に
pdflatex に通して検査する。上の表に無い依存が増えたら落ちる。逆に、表に
あるものが依存無しで通るようになっても落ちる（表が古びないように）。
## 3. 画面構成

```text
┌ タイトル: <ファイル名> [*] — 数式エディタ64 [操作ログ記録中] ─────┐
│ メニュー: ファイル / 編集 / 挿入 / 表示 / TeX / ヘルプ              │
├ 分類タブ: 基本 | 解析 | 集合・記号 | 幾何 | ギリシャ ─────────────┤
├ 選択分類パレット（最大5個）│ 常設書体: R x | I x | B x ─────────┤
│                                                                    │
│ 数式キャンバス（常時表示、既定は左寄せ）                         │
│                                                                    │
├ TeXソース ──────────────────────────────────────────────┤
│ \frac{x}{y}  （複数行EDIT、常時表示）                             │
└ ステータス: 状態 | キャレット | ズーム | 入力スタイル | ヒント ─────┘
```

子コントロールは上からパレットバー、キャンバス、TeXソース見出し、TeXソース欄、
ステータスバーの順に配置し、相互に重ねない。TeXソース欄は常時表示し、内容領域の
およそ4分の1（logical 76--150 px）を使う。表示切替は設けない。

### 3.1 タイトルバー

- 未保存は `無題.tex`、保存済みはファイル名を表示する。
- 変更ありのときはファイル名の後ろに `*` を表示する。
- 操作ログ中は `[操作ログ記録中]` を付加する。

### 3.2 メニュー

| メニュー | 必須項目 |
|---|---|
| ファイル | 新規、開く、保存、名前を付けて保存、SVG書き出し、終了 |
| 編集 | Undo、Redo、切り取り、コピー、貼り付け、すべて選択 |
| 挿入 | 基本、解析、集合・記号、幾何、ギリシャの5分類。各分類内はパレットごとの列に分け、全項目を直接提示 |
| 表示 | 拡大、縮小、ズームリセット、編集記号を表示 |
| ヘルプ | 操作一覧、ショートカット・コーチ、操作ログ、F12目印、第三者ライセンス、About |

### 3.3 パレットバー

Eqnedt32にならい、ツールバーは**挿入できるものの総目録**とする。ただし18個を
同時表示せず、Web版と同じ5分類タブを1段目、選択分類のパレットを2段目に置く。
パレットを押すと格子を開き、セルを選ぶと記号または構造を挿入する。

| 分類 | パレット |
|---|---|
| 基本 | 分数と根号、上下付き、行列、括弧、装飾 |
| 解析 | 関係演算子、演算子、その他の記号、総和、積分 |
| 集合・記号 | 矢印、集合記号、論理記号、総乗と集合演算、空白と点 |
| 幾何 | 上線と下線 |
| ギリシャ | ギリシャ小文字、ギリシャ大文字 |

- 分類内のパレットは固定幅・固定順とし、目的の位置を覚えられるようにする。
- 基本はWeb版と同じ学習順「構造→括弧→装飾」とし、構造内は分数・根号、
  上下付き、行列の順に置く。集合・記号も高頻度の矢印・集合を左に置く。
- どの分類も最大5パレットとし、横幅を増やしすぎない。
- `R x`（立体）、`I x`（変数・斜体）、`B x`（ベクトル）は分類に属さない
  共通書体なので、2段目の固定位置へ常時表示する。分類を切り替えても動かさない。
  保存TeXは旧宣言形の `\rm` / `\it` / `\bf` ではなく、範囲が明確な
  `\mathrm{...}` / `\mathit{...}` / `\mathbf{...}` とする。
- キャンバスに選択範囲があれば即座にその書体へ変更し、選択がなければ次の文字以降の
  継続入力スタイルにする。TeXソース欄では選択範囲をコマンドで包み、選択がなければ
  空の `{}` を挿入してその内側へキャレットを置く。
- 使用頻度の低い `\mathsf` / `\mathtt` / `\mathcal` / `\mathbb` /
  `\mathfrak` / `\bm` は基本分類の「装飾」に置く。`\boldsymbol` は
  `\bm` の入力別名、`\mathnormal` は標準書体へ戻すリセットとして扱う。
- パレットの格子は左から右へ読む順に並べる。
- 行列パレットは1×2、1×3、2×1、2×2、2×3、3×1、3×2、3×3、4×4、5×5、6×6と、
  行／列の追加／削除を提示する。固定サイズの網羅ではなく、よく使う形を
  入口として現在セルの下／右へ構造を拡張する。
- セルを選択中はステータス欄へ、実際の挿入コマンドから生成した正規化TeXだけを
  `TeX: ...` と表示する。日本語説明用の別表は作らない。挿入後は同じTeXが常時表示の
  ソース欄へ現れ、新しく挿入された範囲だけを強調する。構造ショートカットも同じ
  強調を出すが、フォーカスと構造キャレットはキャンバスに残す。ソース欄へフォーカスを
  移した時点で一時的な強調選択を解除し、次のTeX入力による意図しない置換を防ぐ。
  コーチ有効時はショートカットをTeXの後ろへ短く併記する。
- 「挿入」メニューも同じ5分類・同じ19パレットを使う。バーとメニューで
  到達できるものが食い違ってはならない。
- パレットの内容は `src/palettes.cpp` を単一の出典とし、
  `tests/test_palettes.py` が「記号表とテンプレート一覧のすべてが
  ちょうど1つのパレットに載る」ことに加え、「全パレットが5分類のどれか
  ちょうど1つに属する」ことを検査する。

### 3.4 数式キャンバス

- 既定は水平左寄せ、垂直は上端から（上余白12px）、ズーム175%とする。
- 左／中央／右寄せは画面上の表示だけに影響し、保存TeXを変更しない。
- 数式の構造と入力穴を描画し、焦点があるときはキャレットと焦点枠を表示する。
- クリックで構造位置を選び、ドラッグで同一構造スロット内を範囲選択する。
- ダブルクリックで現在の構造スロットの内容を選択する。最外スロットでは
  数式全体を選択する。
- `Ctrl+クリック`で、命中した最内側のテンプレートを親スロット内の1構造単位
  として選択する。削除・切り取り・置換で分数線などを中身から切り離さない。
- `Tab` / `Shift+Tab` で構造の次／前の入力穴へ移動する。
- 通常行列内の上下キーは同じ列の前／次の行へ移動する。
- 行列内の `Ctrl+Alt+↓/↑` は現在セルの下へ行を追加／現在行を削除し、
  `Ctrl+Alt+→/←` は右へ列を追加／現在列を削除する。各1は残し、
  最大99×99とする。1操作を1回の名前付きUndo/Redoとする。
- 空の端セルは行列の形の一部である。保存TeXでは `&` の個数を保持し、
  最終空行をそれだけで表せない1列行列でのみ標準的な空グループ `{}` を使う。
  1×N・N×1を含む再読込みで行列を縮めず、通常の空セルでソースを冗長にしない。
- `Enter` で `aligned` 行を作るか、現在行の次に行を挿入する。
- `&` で揃え位置を追加する。
- 積分の上限・下限はTeXのdisplay積分と同じ右上・右下のスクリプト配置とする。
  12 pt基準では本文基線に対して上限約13.2 pt上、下限約10.8 pt下、上限を
  下限より約5.28 pt右へ置く。
- マウスホイールはパン、`Ctrl+ホイール` はズームとする。
- 挿入できる記号・構造は、すべてマウス（パレットバーまたはメニュー）で到達
  できるものとし、ソースへの手打ちだけでしか出せないものを残さない。
  ショートカットは慣れた人の近道であり、パレットは全員の入口である。
  両者は重複してよい——重複を避けて品目を削ると、どちらの経路でも
  到達できないものが生まれる（実際に記号160個中117個がそうなっていた）。
- TeXコマンドはTeXソース欄へ入力する。キャンバスには `\command`＋空白確定の
  入力モードを持たず、キャンバスへ打った `\` は通常の数学バックスラッシュとする。
- 選択範囲があるときの `Ctrl+B` は、選択した記号をその場でベクトル（`\mathbf`）
  にする。
- 編集記号を表示中は、空スロットを点線枠、明示的なTeX空白を青灰色の点、
  `aligned`の`&`整列位置を青灰色の縦ガイドで描く。`Ctrl+Shift+8`で表示を
  切り替える。この表示は画面上だけで、保存TeXとすべての貼り付け／書き出し画像
  には含めない。
- 日本語IMEの変換開始時は構造キャレットの画面座標をIMM32へ渡し、変換文字列と
  候補ウィンドウをその下へ置く。確定した`WM_IME_CHAR`は通常のUnicode文字入力と
  同じ構造経路へ一度だけ通し、取消では数式を変更しない。焦点離脱時は変換状態を
  必ず解除する。

### 3.5 双方向TeXソース

- TeXソース欄は常時表示し、キャンバスと同じ構造モデルを編集する第2の操作面とする。
- ソースの各変更を直ちに構造モデルへ読み、キャンバスを再描画する。閉じ括弧などが
  未入力でも落とさず、EDIT欄には利用者が打ったraw文字列をそのまま残す。
- ソース編集中にキャンバス側を書き換えない限り、正規化済みTeXでEDIT欄を打鍵ごとに
  上書きしない。これにより入力位置を飛ばさず、同期による再帰的な変更通知を起こさない。
- ソースからキャンバスへ焦点を移したとき、キャンバス編集、Undo／Redo、保存、
  新規作成、ファイルを開くときは、構造モデルの正規化済みTeXをソース欄へ反映する。
- ソース欄での連続編集は1つのUndo単位とする。キャンバス側の次の編集または焦点離脱で
  その編集単位を閉じる。
- TeXソース欄は常時表示する。キャンバスとソース欄は、クリックした側をその場で
  直接編集できる。GUI／TeXの入力モードや専用の焦点切替コマンドは設けない。
- ソース欄に焦点があるとき、切り取り、コピー、貼り付け、すべて選択は標準のテキスト
  EDIT操作として働く。Undo／Redoは両画面に共通する構造履歴を使う。
- ソース欄の `Tab` / `Shift+Tab` は次／前の空の `{}` の内側へ移動し、Tab文字を
  挿入しない。該当する空欄がない場合は通常のコントロール間移動へ戻る。

### 3.6 ステータスバー

通常は5区画を表示する。

1. `準備完了` または `● 操作ログ記録中`
2. 構造キャレット位置
3. ズーム率
4. 入力スタイル
5. `Tab`、`Enter`、`&` のヒント

保存完了、コーチ、入力スタイル切替などの一時通知は、ステータスバー全体を
 simple modeで使って表示する。次の通常状態更新時に5区画へ戻す。

- 編集メニューは現在の焦点面と状態から有効性を計算する。選択のないCut/Copy、
  履歴のないUndo/Redo、対応するTeX／文字列形式のないPaste、空式のSelect Allは
  無効にする。無効項目を指したとき、またはアクセラレータで直接呼んだときは、
  「選択範囲がありません」など実行できない理由をsimple modeへ表示する。
- Google スライド用コピーは選択操作ではなく数式全体の専用出力なので、通常の
  Copyとは別に扱い、空式のときだけ無効にする。

## 4. 編集と状態遷移

### 4.1 キャレットと選択

- キャレットは「構造スロットへのパス＋スロット内位置」で保持する。
- 選択は同一スロット内の連続範囲とする。構造スロットを跨ぐ曖昧なドラッグは、
  キャレット移動だけを残し選択を解除する。
- 選択中の文字入力、TeX貼り付け、テンプレート挿入は選択範囲を置換する。
- Undo / RedoはTeX正規化文字列、キャレット位置、操作名を復元する。
  `Typing`、`Template`、`Style Change`、`TeX Edit`など、次に戻す／やり直す
  操作名を編集メニューと操作ログへ同じ表記で出す。
- **Backspaceは1回につき、利用者に見えるものを1つだけ消す。** 直前がテンプレート
  なら、中身の残っている一番奥のスロットから最後の1項目だけを取る。テンプレート
  自体が外れるのは、全スロットが空になってからとする。
  例：`E = mc^{2}|` → `E = mc^{}|` → `E = mc|` → `E = m|`。
  `\sqrt{x^{2}}|` → `\sqrt{x^{}}|` → … と1項目ずつ剥がれる。
  この項は事例ではなく規則である。過去にこの箇所は報告された1状態だけを直し、
  同じ状態だけを試験したため、隣の状態（母数のあるスクリプトの直後にキャレット）
  が壊れたまま残り、`E = mc^{2}` が1打鍵で `E = m` になった。以下の2項は
  この規則から導かれる個別例であって、規則の全体ではない。
- Backspace / Deleteの対象が空の上付き・下付きスロットを持つスクリプトなら、
  空スロットだけを除く。他の添字と基底は保持し、添字が一つも残らない場合は
  基底を親スロットへ戻す（例：`E = m{c^{2}}^{}` → `E = mc^{2}`）。
- 上付き・下付きスロット内にキャレットがある場合、Backspaceは通常どおり直前の
  文字を1文字削除する。`H^{2}|`は1回で`H^{}|`、もう1回で`H|`となる。

### 4.2 入力スタイル

| 状態 | 保存TeXの意味 |
|---|---|
| 数学（既定） | 数字、変数、数学記号を自動判定 |
| 文字列 | `\text{...}` |
| 関数 | `\sin`などの標準関数、または `\operatorname{...}` |
| 立体 | `\mathrm{...}` |
| 変数（斜体） | `\mathit{...}` |
| ギリシャ | 対応するTeXギリシャ文字コマンド |
| ベクトル | `\mathbf{...}` |

入力スタイルは次の文字以降に継続し、表示だけでなくTeX構造として保存する。
数学スタイルで逐次入力した英字列が既知の関数名（`sin`、`log`、`exp`など）に
到達した時点で関数スタイルへ自動変換し、その後に引数変数を続けても関数書体を
保持する。たとえば`sinx`の逐次入力は`\sin x`となり、`sin`は立体、`x`は斜体に
する。`sin`の直後に`h`を入力して`sinh`になった場合は、より長い関数名を優先する。
Eqnedit32から継承する自動認識名は次の39個である。

`Im`, `Pr`, `Re`, `arg`, `arcsin`, `arccos`, `arctan`, `cosh`, `cos`,
`coth`, `cot`, `cov`, `csc`, `deg`, `det`, `dim`, `exp`, `gcd`, `glb`,
`hom`, `inf`, `int`, `ker`, `ln`, `lg`, `lim`, `log`, `lub`, `max`, `min`,
`mod`, `sec`, `sgn`, `sinh`, `sin`, `sup`, `tanh`, `tan`, `var`

Eqnedit64拡張として、`curl`, `div`, `grad`, `rot`, `tr`, `diag`, `Res`,
`const`も同じ規則で立体化する。
文章を入力する場合は文字列スタイルを使用する。

### 4.3 文書状態

| 操作 | 状態変化 |
|---|---|
| 新規 | 未保存の場合は保存確認後、空の数式、`equation`保存、変更なしへ初期化 |
| 開く | 未保存の場合は保存確認後、対象TeXを構造化して変更なしで表示 |
| 編集 | dirtyを立て、タイトルへ `*` を表示 |
| 保存 | UTF-8 `.tex` を同一ディレクトリの一時ファイル経由で書いてから置換し、dirtyを解除。書き込みに失敗した場合は元のファイルを変更しない |
| 終了 | dirtyの場合は「はい／いいえ／キャンセル」で保存確認 |

## 5. TeXファイル契約

- 文字コードはUTF-8とする。
- 開いた文書に `equation` / `equation*` がある場合は、最初の対象環境を編集する。
- 対象環境の前後にあるTeX文書文字列は保存時に維持する。
- 対象環境がない場合は、全体を数式断片として読み込む。
- 新規文書の保存時は編集中の数式を1つの `equation` で包む。開いた文書の対象環境が
  `equation*` だった場合だけ、その外枠を保存時にも維持する。番号切替UIは設けない。
- 2行以上または複数揃え列は `aligned` と `&` / `\\` で保存する。

## 6. クリップボード契約

### 6.1 キャンバスからのコピー

1回のコピーで次の形式を同時登録する。貼り付け先が対応する最適な形式を選ぶ。

| Windows形式 | 内容 | 主な利用先 | 契約 |
|---|---|---|---|
| 登録形式 `MathML` | 24 pt基準のPresentation MathML | Microsoft 365 PowerPoint / Word / Excel | 必須 |
| 登録形式 `MathML Presentation` | `MathML`と同じPresentation MathML | Microsoft 365 PowerPoint / Word / Excel | 必須 |
| 登録形式 `HTML Format` | 上記と同じinline MathML + 末尾NBSPのCF_HTML | Microsoft 365 PowerPoint / Word / Excel、Web版fallback MathMLとの共通契約 | 必須 |
| `CF_UNICODETEXT` | `\[<正規化TeX>\]` | 旧Office、通常の文字貼り付け | 必須 |
| 登録形式 `LaTeX` | 外側区切りなしのraw UTF-8 TeX断片 | TeX対応ソフト | 必須 |
| `CF_ENHMETAFILE` | 白背景のスケーラブルEMF | IrfanView、Office、画像ソフト | 必須 |
| `CF_DIBV5` | 全画素α=255の白背景・黒文字、32-bit top-down DIB、原則192 dpi | ラスター貼り付けフォールバック | 必須 |

- Microsoft 365 PowerPoint / Word / Excelはinline CF_HTMLまたは登録Presentation
  MathMLを編集可能なOffice Mathとして取り込む。3形式のMathML本体は同一とし、
  Web版のfallback MathMLもinline・24 pt・同じ総和／積分limit規則へ正規化し、
  PowerPoint用の条件付きOMMLで同じ意味構造を保つ。ブラウザHTML取り込みは18 pt、
  EXEの登録MathML取り込みは24 ptである。Office自身の書き出し画像と保存OOXMLで、
  分数・根号・総和・積分・上線・下線構造が見えることを必須とする。
- 通常コピーへPNGを混在させない。PowerPointが画像を優先して編集不能な貼り付けへ
  退化するためである。EMF/DIBV5は画像ソフト用のWindowsフォールバックとして残す。
- TeX対応ソフトは登録形式 `LaTeX` のraw断片を利用できる。
- コピー時はユーザーの選択か数式全体を、同じ構造木から全7形式へ変換する。
- 切り取りは全必須形式を公開できた場合に
  限って選択範囲を削除する。

### 6.2 Google スライド用コピー

「編集 → Google スライド用コピー」または `Ctrl+Alt+C` は、通常コピーとは別に
次の2形式だけを登録する。通常コピーへ混在させてPowerPointの貼り付け形式選択を
画像へ変えてはならない。

| Windows形式 | 内容 | 契約 |
|---|---|---|
| 登録形式 `PNG` | 24 pt基準の数式を300 dpiで描画したsRGB PNG | 必須 |
| 登録形式 `HTML Format` | 同一PNGのdata URIと、幅・高さをpt単位で指定したCF_HTML | 必須 |

- PNGの `pHYs` は11,811 pixel/m（300 dpi、単位metre）とする。
- PNGの整数画素寸法を300 dpiでptへ戻した値をHTMLのCSS幅・高さに使い、
  Google スライドの縦横比維持で再縮小されないよう完全一致させる。
- HTMLには `data-eqnedit-font-size="24pt"` とpt単位の表示寸法を記録する。
- 選択範囲があればその範囲、なければ数式全体を画像化する。
- Google スライド用コピーは切り取りを兼ねず、数式を変更しない。

### 6.3 コマンドラインTeX→PNG変換

`Eqnedit64.exe --texclip` はウィンドウを表示せず、クリップボード上のTeXを
読み取って、登録形式 `PNG` の白背景画像に置き換えて終了する。

- 入力は登録 `LaTeX`（UTF-8 raw断片）を優先し、なければ `CF_UNICODETEXT` を読む。
- 外側の数式区切り・環境は6.4と同じ規則で正規化する。
- 出力は24 pt基準、300 dpiで描画し、`pHYs` を11,811 pixel/mとする。
- 登録 `PNG` を正本とし、Windows貼り付け互換用に同じ300 dpi画像の
  `CF_DIBV5` を併記する。DIBV5も白背景・黒文字かつ全画素α=255とする。
- Google スライド用の `HTML Format` は混在させない。
- 成功は終了コード0、空入力は83、画像化／クリップボード登録失敗は84とする。
- `--clipboard-tex-to-png` は同一機能の説明的な別名とする。

### 6.3.1 公開コマンドラインAPI

- `--copy-tex[-file]`: 任意TeXを通常コピーと同じOffice Math、TeX、EMF、
  不透明DIBV5の組としてクリップボードへ登録する。
- `--copy-google-slides[-file]`: 任意TeXを6.2のPNG+HTMLとして登録する。
- `--copy-png[-file]`: 任意TeXをPNG+DIBV5だけとして登録する。
- `--render-png[-file]` / `--render-emf[-file]`: 任意TeXを指定ファイルへ書く。
- `-file` 形式の入力はUTF-8 `.tex`で、外側の数式環境・区切りを6.4と同様に除く。
- すべて非表示で動作し、前面ウィンドウ、マウス、キーボードを操作しない。
- 成功0、入力ファイル読込み失敗82、空入力83、クリップボード失敗84、
  引数不足94とする。

### 6.4 キャンバスへの貼り付け

- `CF_UNICODETEXT` を読む。
- クリップボード全体を囲む `$...$`、`$$...$$`、`\(...\)`、`\[...\]`、
  `equation`、`equation*` だけを外す。
- `aligned`、行列、場合分け、添字、分数など意味のある内部構造は保持する。
- TeX区切りがないUnicode文字列も受け入れる。
- 構造選択がある場合は選択範囲を置換する。

## 7. キーボード契約

- 完全なキー定義は [`SHORTCUTS.md`](SHORTCUTS.md) を正とする。
- Eqnedit32互換の `Ctrl+T`、`Ctrl+K`、`Ctrl+G`、`Ctrl+B` 接頭辞を維持する。
- 接頭辞後の未登録キーは何も挿入せず、ステータスで通知する。
- `Esc`、焦点移動、または別の操作で未完了の接頭辞を解除する。
- メニューやツールバーから構造を挿入した後は、コーチ有効中のみ対応キーを通知する。

## 8. エラーと確認ダイアログ

- 未保存文書の新規、開く、終了の前に保存確認を出す。
- 保存失敗、ログ作成失敗はエラーダイアログで通知する。
- コピー失敗はステータスで通知し、切り取りであっても数式を削除しない。
- 操作ログなしで `F12` を押した場合は、先にログを開始するよう通知する。
- ユーザーの文書を自動修復、自動上書き、自動送信しない。

## 9. 操作ログ

- 既定は無効とする。
- 有効時は `%LOCALAPPDATA%\Eqnedit64\logs\operation-*.log` へUTF-8 BOM付きで記録する。
- operation log v2として、操作、単調時刻による開始後時間／イベント間隔、
  キャレット、選択、dirty状態、TeX数式、焦点、入力スタイル、表示配置、ズーム、
  式番号状態、ショートカット接頭辞を記録する。
- ログに研究内容が入る可能性を開始時とガイドで通知する。
- `F12` はその時点の状態に `user.marker` を追加する。
- 旧operation log v1はLLM操作感分析器で引き続き読めること。
- LLM操作感分析は既定で数式本文をハッシュ／構造概要へ置換し、自動送信しない。
- 摩擦検出は候補抽出であって欠陥判定ではない。LLM提案だけで動作を変更せず、
  人間の採否、選好台帳、非表示回帰試験を必要とする。

## 11. 仕様変更のルール

- GUI動作を変更する場合は、実装と同じ変更でこの文書を更新する。
- キー割当の変更は `SHORTCUTS.md` とショートカット試験も同時に更新する。
- 受入条件を自動化できる場合は、手動試験に残さず回帰試験へ追加する。
- APIで検証できる外部アプリ連携は回帰試験へ追加し、人間の視覚・操作感だけを手動試験に残す。
- 仕様と実装が食い違う場合は、仕様を曖昧なまま実装に合わせず、どちらが
  製品意図かを決めて両方を同時に修正する。
