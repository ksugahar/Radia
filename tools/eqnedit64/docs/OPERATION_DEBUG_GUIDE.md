# Eqnedit64 操作デバッグガイド

操作デバッグは、利用者が普段どおりに数式を編集し、その操作と内部状態を
ログに残して不具合を再現するための機能です。マウスやキーボードを外部から
自動操作するものではありません。

## 開始と終了

1. `Eqnedit64.exe` を起動し、「ヘルプ → 操作ログを記録」を選びます。
2. タイトルに `[操作ログ記録中]`、ステータスバーに `● 操作ログ記録中` と
   表示されることを確認します。
3. 普段どおり操作します。違和感が起きた直後に `F12` を押してください。
4. 「ヘルプ → 操作ログを記録」をもう一度選び、記録を終了します。
5. 「ヘルプ → 最後の操作ログを表示」でログファイルを確認します。

ログは通常、次のフォルダーへ保存されます。

```text
%LOCALAPPDATA%\Eqnedit64\logs
```

ログには、キーやメニューの操作、キャレット位置、選択範囲、編集中のTeX数式が
記録されます。未公開の数式を入力した場合は、共有範囲に注意してください。

## GUI試験の分担

日常の回帰試験は画面を操作せず、非表示ウィンドウでステータスバーの区画順序、
矩形、フォント高、通常表示と一時メッセージ表示の切替を調べます。非表示のキャンバスへ
Win32メッセージを直接送り、文字入力、補助平面文字、Undo、テンプレート、ソース欄、
表示コマンドの実際のウィンドウプロシージャも通します。数式そのものは
メモリ上へ描画して検査します。PowerPointとIrfanViewへの実貼り付けも、COMと
コマンドラインAPIで自動検査します。実画面で確認するのは文字の見た目と操作感です。

この分担により、自動試験が作業中のマウスやキーボードを奪うことはありません。

## 初回の操作確認

次の順に試すと、主要な操作を一巡できます。期待どおりでない箇所があれば、
その場で `F12` を押し、続けて同じ操作をもう一度だけ行ってください。

| 番号 | 操作 | 期待する結果 |
|---:|---|---|
| 1 | `Ctrl+A` の後に `y=` を入力し、`Ctrl+F` | 分数の上下に空欄が現れる |
| 2 | 分子へ `a+b`、`Tab`、分母へ `c+d` | `y=(a+b)/(c+d)` の分数構造になる |
| 3 | `Ctrl+H`、`2`、`Esc` | 選択位置に上付き2が入り、構造外へ戻れる |
| 4 | 左右キー、`Shift+左右キー` | キャレット移動と範囲選択が目で追える |
| 5 | 選択範囲を `Ctrl+C`、`Ctrl+V` | TeX構造を保ったまま複製される |
| 6 | `Ctrl+Z`、`Ctrl+Y` | 貼り付け前後を往復できる |
| 7 | `Ctrl+A`、`F&=ma`、`Enter`、`E&=mc`、`Ctrl+H`、`2` | 2行のaligned数式になる |
| 8 | 上下キーと `Tab` / `Shift+Tab` | 行と入力欄の間を移動できる |
| 9 | マウスで一部をドラッグし、文字を入力 | 選択部分だけが置換される |
| 10 | `Ctrl+S`で`.tex`保存後、閉じて再度開く | equation/aligned構造が維持される |
| 11 | `\[\frac{x}{y}\]` をクリップボードから貼る | 外側の `\[...\]` を除いた分数になる |
| 12 | Ctrl+マウスホイール、Ctrl+0 | 拡大縮小後に標準倍率へ戻る |

入力中の数式は既定で左寄せされ、式が長くなっても開始位置は動きません。
`Ctrl+Shift+C` で中央、`Ctrl+Shift+R` で右、`Ctrl+Shift+L` で左へ戻せます。
この表示配置は、保存したTeXの組版配置には影響しません。

## 外部貼り付けの自動試験

PowerPoint、IrfanView、登録 `LaTeX` 形式、Google スライド用画像は次のコマンドで
検査します。

```powershell
pwsh -Sta -NoProfile -File build\test_external_paste.ps1
```

試験はEqnedit64から実クリップボードへ数式を発行し、PowerPointの通常 `Paste()`、
IrfanViewの `/clippaste` を非表示で実行します。PowerPointでは保存した `.pptx` 内の
Office Math XML、IrfanViewでは画像寸法と非白画素を検査します。実行前の
クリップボードは全形式を複製し、形式数とUnicode本文を確認して復元します。
Google スライド用コピーでは、登録PNGとHTMLに埋め込んだPNGが同一であること、
300 dpiの `pHYs`、24 pt基準のpt寸法を検査します。

## 不具合を伝えるとき

次の4点があれば再現しやすくなります。

- 期待した結果
- 実際に起きた結果
- F12を押したおおよその時刻
- 対応する `operation-*.log`

保存前の文書や研究内容を含むログは、必要な相手だけに共有してください。

## LLMで操作感を分析する

ログ記録後、最新のログからレビュー束を作成できます。

```powershell
pwsh -NoProfile -File build\analyze_last_operation_log.ps1
```

出力は `C:\temp\Eqnedit64-usability-*.json` です。既定の`structure`モードは
数式本文、選択内容、入力詳細を伏せ、長さ、ハッシュ、TeX構造だけを残します。
内容を含める必要があり、ローカルの許可されたLLMへだけ渡す場合は
`-Privacy full`を明示します。

LLMはF12前後のイベント番号を引用し、違和感の仮説、Eqnedit32の根拠、最小変更、
バックグラウンド再現試験、人間に確認すべき一点を返します。検出器やLLMの判断だけで
ショートカットや動作を変更しません。詳しい契約は
[`LLM_USABILITY_ENGINE.md`](LLM_USABILITY_ENGINE.md)を参照してください。
