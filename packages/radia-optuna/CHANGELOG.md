# Changelog

## 0.5.0 (2026-11-01)

- Replace the mexcuda build route with one nvcc-compiled CUDA object in a
  CMake static library shared by Python/pybind11 and plain MSVC MEX adapters.
  On reviewed source `0acab7dec`, Windows RTX 5000 checks passed the stored
  CPU/GPU oracle cases, same-kernel density bitwise parity and existing MATLAB
  compatibility tests. Publication requires final 0.5.0 artifacts to pass their
  own exact-source installed-wheel acceptance; the historical measurements
  below do not certify this route.
- After an owned GPU context reset, stale prepared allocations fail loudly.
  Explicit clear and rebuild preserved density bits, and the MATLAB host RNG
  snapshot stayed unchanged. Silent rebuilding or CPU fallback is prohibited.
  These checks do not certify address reuse, every exit exception path or CUDA
  destructor ordering. These checks do not qualify the new route on A100.

## 0.4.0 (2026-10-13)

- The 0.4.0 release selected CPU/OpenMP or CUDA GPU execution explicitly within the same mexcuda module. GPU was the compatible process default; device failures raised.
- Cache eligible exact-name history and ranking without discarding trials or changing seeded random consumption.
- Construct native TPE bandwidths, categorical probabilities and density normalizers on GPU; retain ordered sampling RNG on the host.
- Reuse bounded device workspaces, use CUB sorting for large models and parallelize mixture exponentials with ordered final summation. Preserve reset, failure and unload behavior.
- Tune CPU/OpenMP dispatch and reuse CPU normalizers for fair comparisons.
- Preserve the Optuna 5.0.0 oracle contract with focused CPU/GPU checks. Formal A100 evidence shows a 2.44x joint-TPE gain at 40 variables/5,000 starting observations and 1.23x warmed complete inference on the 40D sequential benchmark; small/independent cases show no general GPU advantage.

See README.md and linked machine-readable validation records for scope and limitations. These measurements do not claim complete upstream API coverage or Python/DB, Rustuna or BoTorch speedups.

Notable changes to the independently released `radia-optuna` distribution.
Releases before 0.2.0 are recorded only by their `radia-optuna-v*` tags.

## 0.2.0 - Optuna 5 design (release candidate)

Changes since `radia-optuna-v0.1.6`. Publication requires the exact main-CI
wheel to pass the four-machine `release_quad optuna-candidate` gate and
`optuna-done`; until then this is a candidate.

- **Optuna 5 design adopted in place.** Shared MATLAB behaviour (seeds,
  options, parameter and search-space order, history, named constraints,
  values, states, warnings, defaults and random consumption) is judged only
  against fixtures generated by pinned `optuna==5.0.0`. The Optuna 4.9
  fixtures and pins, removed APIs and options, legacy sampler-state restore
  and the separate public multi-objective TPE are deleted; the unified
  `TPESampler` owns single- and multi-objective studies.
- **Constructor defaults are oracle-checked.** The oracle records every
  defaulted public constructor parameter, so a changed default (Optuna 5.0:
  `TPESampler` `multivariate=None`, `constant_liar=True`) fails the coverage
  gate instead of silently changing seeded results. Ambiguous evidence fails
  closed.
- **Toolbox-style entry points.** `radia.optuna.getParameterFromModel`,
  `radia.optuna.optimoptions` and the `OptimizationSession` lifecycle drive a
  study in Global Optimization Toolbox / `sdo.optimize` vocabulary on top of
  the existing study.
- **Storage bridge.** `radia.optuna.export_study` / `import_study` exchange a
  `radia.optuna.study-export.v1` document, so a table/MAT study can be opened
  from Python Optuna storages.
- **Simulink.** Python-backed samplers stay outside Simulink time steps;
  masks prefer the unified multi-objective TPE and keep sampler names.
- **Performance, behaviour unchanged.** Native TPE history is reused and
  rebuildable for persisted studies, persisted trial snapshots are flattened
  for verified MAT saves, and sampler-state table churn is reduced. Measured
  results and host limits are recorded in the package review documents.
- Pruned trials are honoured in CMA-ES and multi-objective TPE histories.
