# Analytical HDF5 branch fixture

`B_input.hdf5` stores the analytical branches generated by `CASE_02.m`, not
measurements from a specimen. The original MAT numeric arrays were migrated
without changing their shapes, dtypes or C-order raw bytes. The historical MAT
SHA-256 remains in `../../hdf5_fixture_migration.json`; it is provenance, not an
operational input or fallback. The original is retained outside tracked source.

Schema `radia.hysteresis-branches.v1` stores `/dB`, `/BMax` and
`/BH/0000/H`, `/BH/0000/B`, ... in original struct-column order (zero-based).
Each dataset retains the original MATLAB logical shape, with explicit SI units:
H in A/m, B/BMax/dB in tesla. UTF-8 attribute names describe layout, numbering,
labels and unknown generation metadata. C-order SHA-256 identifies each raw
numeric payload, including sign bits and NaN payloads if present. Python h5py
uses the disk shape directly. MATLAB high-level h5read reverses disk dimensions;
transpose/permute to restore the documented logical shape. The generator applies
the inverse permutation when writing. Regenerated bytes need not match file
hashes; generation itself was not rerun during this migration.

The branch spacing is 0.095 T, with 20 levels up to 1.9 T. `Ms=1.91` in the
analytical generator is a flux-density-scale quantity, not magnetization A/m.
`../../verify_fixture_lineage.py` reidentifies all 128 committed NPZ fields using
the HDF5-only reader. `../../fixture_lineage.json` records that verification.
The migration and lineage checks do not qualify a coupled field solve.
